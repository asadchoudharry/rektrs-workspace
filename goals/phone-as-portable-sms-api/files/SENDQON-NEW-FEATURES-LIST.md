## NF-1 — Postqon ke liye asal one-click OAuth connect (Sendqon-side izafa)

**Registered:** 2026-11-19 (owner, via the Postiz chat) · **Status:** ✅ BUILT (Sendqon-side) — 2026-11-20, owner ke "Baki new features per bhi Kam Ker" par. Report: `SENDQON-NF1-REPORT-2026-11-20.md`. Postqon-side implementation (social.rektrs.com par connect button + callback) is ke scope se bahir tha — wo alag lane hai.

**Context:** Postqon (social.rektrs.com) ka Sendqon Connector v1 ban chuka hai — user apni API key paste karke Connect & test karta hai. Asal one-click connect ke liye Sendqon ki taraf se ye chahiye:

1. **Postqon ko first-party OAuth client ke tor par register karna** — redirect URI: `https://social.rektrs.com/developers/sendqon/callback`. Sath confirm karna ke OAuth se mila token aam REST Bearer ke tor par send abilities (`wa.send`, `sms.send`, `account.view`) ke sath kaam kare. **Maujooda haal:** OAuth ka istemal abhi sirf MCP endpoint par proven hai, aur wo plan `mcp` flag ke peeche hai — **plan gating ka faisla bhi isi item ka hissa hai** (kis plan par OAuth-issued REST tokens chalenge).
2. **Media-upload endpoint ko customer OpenAPI/docs mein publish/confirm karna** — endpoint mojood hai aur Postqon ki taraf se pin ho chuka hai: `POST /api/v1/whatsapp/media`, field `file`, ≤ 51200 KB, top-level `media_path` return karta hai. Sirf documentation wala hissa baqi hai.
3. **(v2 nicety) `GET /api/v1/whatsapp/accounts`** — taake Postqon workspace ke default number par khamoshi se bhejne ke bajaye user ko number SELECT karne de sakay.

### Kya bana (2026-11-20, DEV battery 34/34 PASS + production registration)

- **OAuth flow PROVEN end-to-end (DEV):** core ka apna OAuth surface Passport/DCR hai (stock Passport routes nahi — `/.well-known/oauth-authorization-server` + `/oauth/mcp/{register,authorize,token}`). Postqon client register (DCR 201) → consent → authorization code seedha `https://social.rektrs.com/developers/sendqon/callback?code=…` par → PKCE (S256) token exchange 200 + refresh token → token se `get-account` (account.view) 200, `send-sms` (sms.send) 202 + message row, `send-wa-message` (wa.send) ability honoured (DEV tenant ke pas connected WA account na hone par controller ka `no_wa_account` 422 — scope refusal nahi).
- **⚠️ Aik design sachai jo Postqon-side lane ko zaroor maloom ho:** OAuth token (Passport JWT) **seedha `GET /api/v1/...` par Bearer nahi chalta** — plain REST surface Sanctum-PAT-only hai (JWT → 401, battery-proven, by design). OAuth token ki REST abilities (`wa.send`, `sms.send`, `account.view` — yahi teeno ability names) core ke **MCP dispatch channel** (`POST /mcp`, tools: `send-sms`, `send-wa-message`, `get-account`, … kul 29) ke zariye exercise hoti hain; andar se wahi `/api/v1` routes + wahi ability/RBAC/send-limit checks chalte hain. Plain REST ke liye tenant apna Sanctum PAT khud banata hai (API Tokens screen). Postqon connector ko isi MCP channel par design karna hoga.
- **Gating (coordinator ka faisla, isi tarah implement):** OAuth tokens **existing `mcp` plan flag** ke tehat hain — flag off ho to maujooda token 401, refresh `invalid_grant`, nayi consent par workspace offer hi nahi hota (battery-proven, DEV par plan surgery + restore ke sath). **Master admin bila qayd** — plan ka `mcp` off hone par bhi admin ka flow pura chalta hai (proven). Koi nayi pricing invent nahi ki gayi; `mcp` flag kis plan mein on hoga ye owner ka pehle se pending pricing faisla hai (production ke tamam 7 plans par abhi `mcp=false` hi hai — untouched).
- **Media endpoint docs:** `POST /api/v1/whatsapp/media` pehle se core ke published OpenAPI contract (`resources/contracts/public-v1.yaml`, in-dashboard `/api-docs` + public `/api` page se serve hota hai) mein documented hai — field `file`, ≤ 50 MB, 201 response mein top-level `media_path` + `media_url`; DEV battery: 401 (no token) / 403 (no `wa.send`) / 201 + `media_path` (valid PNG) / 422 (ghalat mimetype). **Koi docs change zaroori nahi tha** — endpoint pinned contract ke mutabiq pehle se live + documented hai; production par bhi yaml + unauth 401 spot-check PASS.
- **Accounts endpoint:** `GET /api/v1/whatsapp/accounts` **pehle se core mein maujood tha** (ability `wa.accounts.view`, cursor pagination) — koi core patch nahi laga (PR-register untouched). DEV battery: 401 unauth; tenant isolation (dusre tenant ka account 404, list mein leak nahi); empty state `data: []`; picker fields `id, user_id, wa_server_id, jid, phone, display_name, label, status`. Production par route live (unauth 401).
