## Item 1 — AI Flow Builder (ai_integration) — ✅ BUILT + LIVE (tenant access plan-gated off)

- **What:** Core carries the whole gate + HTTP surface (`FlowAiController`, `AiFlowBuilderAccess`, plan flags `flows` + `ai_flow_generation`, the `ai-flow-generation` rate limiter, the editor's AI panel + draft notice UI). The plugin supplies the one class core resolves by name — `App\Plugins\AiIntegrations\AiFlowBuilder\FlowBuilder` implementing core's `FlowAiBuilder` contract (`generate` / `draftInto` / `editTurn`) — plus a plugin-owned edit-history table. The prompt's node catalogue is generated from core's **live** `NodeTypeCatalog` (72 types), so prompt and validator can never drift. Drafts are normalised (catalogue defaults filled, ids sanitised, layout assigned, edges checked against real output handles; `tag_names`/`group_names` resolved to workspace ids exactly like core's own template builder — tags firstOrCreate, groups never invented), then engine-validated with core's `FlowValidator` + network-permission check **inside the gateway's charge transaction**: an invalid draft throws, the charge is refunded, nothing is saved; the validator's errors feed one repair attempt (plugin config, default on). All AI calls go through `AiGateway::complete()` (feature `flow_generation`, idempotency key per request — a repeat of a succeeded request is refused as `duplicate`; a failed attempt never claims the key). Generated flows are created **inactive**; `draftInto` fills an empty inactive flow under an optimistic version check (fail-fast before any AI call); `editTurn` returns the editor's exact proposal shape (`reply`/`proposal`/`diff`/`to_fill`/`not_done`/`tags_created`) and saves nothing. Ready-made templates: core already ships 16 in the New Flow gallery — the builder's prompt steers common requests to those shapes rather than duplicating a template store.
- **No-key test strategy:** dev-only platform provider row (OpenAI type, dummy key, feature price `flow_generation` = 7 credits against a flat 5) + `Http::fake()` at the provider wire returning scripted chat completions (invalid canvas → valid canvas → garbage). The full logic — access gate, generation, repair, duplicate, refund, draft fill, edit proposal, test run — is exercised end to end; only the real provider call is faked.
- **Dev battery: 44/44 PASS** — access (`enabledFor`, props credits = 7.0 feature price, Free plan refused); generate-with-repair (flow created inactive, `trigger_type` derived, `validation_errors` empty, draft notice with `placeholder_text` to_fill, history row; **exactly one charged success at 7 credits, the failed attempt refunded to 0, ledger balance 100 → 93, provider called exactly twice**); duplicate request refused with reason `duplicate`, no second flow, no charge; always-invalid output refused with both attempts refunded and no flow; draftInto wrong-version refused **before any AI call**, correct version fills + bumps version, non-empty flow refused; editTurn returns the editor's exact key set, diff counts the 2 added steps, `tags_created` = [VIP], the stored flow is byte-unchanged, 7 more credits charged; **the generated flow runs in core's FlowTestRunner** (dry-run report, no error, `send.reply` step executed); rollback rehearsed (deactivate → access dark; uninstall → table dropped; reinstall → active). The battery caught two real plugin bugs pre-production: tag steps validate on `tag_ids` (names now resolved in the factory), and the idempotency key must be per-request, not per-attempt (a per-attempt key let a duplicate slip past a repaired success).
