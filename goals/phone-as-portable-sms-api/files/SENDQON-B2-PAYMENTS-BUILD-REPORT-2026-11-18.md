## Item 1 — JazzCash (payment_gateway) — ✅ BUILT + LIVE (unconfigured)

- **What:** Hosted page-redirection checkout per JazzCash's public merchant guide. Signing = all `pp_*` fields except `pp_SecureHash`, sorted by field name (ASCII), values joined `&`, Integrity Salt prepended, HMAC-SHA256 with the salt as key (uppercase hex); `pp_Amount` in paisa. Merchant password is deliberately **not** sent in the redirect (SecureHash is the proof; a password in a URL leaks) — it stays server-side. Settlement converges from the browser return (`/payment/callback?gateway=jazzcash`) and the server-to-server IPN (`POST /api/payment-gateways/jazzcash/webhook`), both hash-verified, one idempotent settle path (Subscription + Transaction `createOrFirst`, user-row lock, activation after commit). Amount/currency mismatch → transaction flagged `needs_manual_refund`, plan NOT activated. `ppmpf_1..5` carry user/plan/kind/install-tag/purchase-ref. Supports monthly/yearly/lifetime (one charge per period), one-time purchases (credit packs/orders) via core's `OneTimePurchaseService`, and the setup-fee contract. No auto-renewal (JazzCash issues no reusable token on this flow). Config: Merchant ID, password (sensitive), Integrity Salt (sensitive), txn type, sandbox toggle + readonly IPN URL.
- **Dev battery: 30/30 PASS** — including the signing implementation matching **JazzCash's own published test vector byte-for-byte** (salt `3vv9wu3a18` example → `2C595361…B117`), checkout URL shape (sandbox host, paisa amount, no password in URL, hash self-verifies), valid simulated IPN → subscription ACTIVE + transaction completed + plan assigned, duplicate IPN → core `already_processed` with exactly 1 transaction/subscription, tampered IPN → 400 with zero state change, correctly-signed wrong-amount IPN → recorded + `needs_manual_refund` + no activation, one-time purchase IPN → completed, empty config → `isConfigured()` false + checkout throws, uninstall (after clearing battery subscriptions — core guards uninstalls with live subscriptions) → webhook 404, reinstall → active.
- **Production:** fresh backup first (status=OK, push=OK). Installed via `PluginManager::installFromZip` — **status=inactive, config empty** (activation is refused by the app until configured; owner activates after entering merchant credentials). Live-safe checks: site 200, /login 200, inactive-gateway webhook 404, all containers Up. Baked into host build tree `~/sendqon-build/src/app/Plugins/PaymentGateways/JazzCash/`.
- **Pending:** **PENDING-MERCHANT-ACCOUNT** — no JazzCash merchant account exists yet. Owner step: obtain JazzCash merchant credentials → Admin → Plugins → JazzCash → Configure (Merchant ID / Password / Integrity Salt) → set the IPN URL in the JazzCash portal → Activate → first live/sandbox charge verifies end-to-end.
