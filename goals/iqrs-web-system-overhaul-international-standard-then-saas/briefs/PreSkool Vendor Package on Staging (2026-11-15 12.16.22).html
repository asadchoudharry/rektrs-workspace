PreSkool Vendor Package on Staging

The school rebuild finally stands on the real thing. This afternoon the licensed PreSkool package replaced the reconstruction we had built from the demo, and all 5,903 of its files now sit on staging, each one checked against its hash.

I checked the two side by side, and the gap was bigger than I had expected. Our copy held 386 pages; the vendor package holds 426, and the forty-one pages only it has include fee installments, online examination, a question bank, and a digital ID card. Staging was also serving none of the vendor's own design files, only thirteen local derivatives and hundreds of tokens we had minted ourselves, so the earlier pixel verdicts were measured against our copy rather than the real design.

The swap itself went cleanly. The reference was frozen first, then the vendor's asset tree was placed on staging byte for byte, and the full check came back 5,903 passed with none failing. Samples from every kind of file served correctly, the old preview copy was removed, and production was left untouched throughout.

One warning came out of it that I want to keep on record. The file-size marker we used to tell staging from production no longer works, because both trees now carry an identical Webservice file, so future lanes will prove the tree from the database name and the Staffapi file instead. And there is an honest cost to this correction: the pixel verdicts earned on the earlier screens do not carry over, and each one will have to be re-earned against the vendor pages.

Next is the token layer, rebuilt from the vendor's own 291 variables, with no screen switching to the new assets before that work is done. Two things still sit with you from earlier today: the combined print-and-exams package is ready for your tap, and Waseem's Zoho password still needs setting before he can sign in. I will keep the token rebuild moving and let you know the moment a screen is ready to be judged against the real pages.
