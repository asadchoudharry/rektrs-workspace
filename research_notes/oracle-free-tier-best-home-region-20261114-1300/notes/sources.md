# Source notes — read 2026-11-14 (PKT evening), index + browser_open

## Official Oracle (verified via browser_open, 2026-11-14)
- https://docs.oracle.com/iaas/Content/FreeTier/resourceref.htm — Always Free Resources: A1 = first 1,500 OCPU-h + 9,000 GB-h/mo, = 2 OCPU/12 GB for Always Free tenancies; up to 2× E2.1.Micro; A1 in any AD except Chuncheon; E2.Micro only in ONE AD in multi-AD regions; min boot 47 GB; 200 GB block total; out-of-host-capacity = temporary lack of Always Free shapes in home region, try other AD/wait/upgrade PAYG (Oracle doesn't charge for Always Free after upgrade, only above limits); idle reclaim: 7 days, CPU p95 <20% AND network <20% AND memory <20% (A1 only for memory).
- https://www.oracle.com/cloud/free/faq/ — Free Tier available in all regions where commercial OCI available***; "If your first-choice data region isn't available, select an adjacent region"; PAYG accounts "subject to different capacity limits than Always Free accounts"; out-of-host-capacity may take several days; accounts idle 30+ days may be deemed abandoned; one account per person; over-limit A1 at trial end disabled then deleted after 30 days unless upgrade; $300/30-day trial.
- https://signup.cloud.oracle.com/translations/en-US/translation.json — signup UI strings: Billing Country/Territory is separate, "Home region will be selected later"; home region "not changeable after sign-up"; "Free Tier is not available in all commercial data regions. Please select the data region that is closest…"; "any region may or may not have availability… do not attempt to create multiple accounts in order to change regions"; no virtual/prepaid/single-use cards.
- https://docs.oracle.com/en-us/iaas/Content/General/Concepts/regions.htm — commercial region table with AD counts: ONLY Frankfurt, London, Ashburn, Chicago, Phoenix have 3 ADs; all others listed have 1 (incl. Sydney, Hyderabad, Mumbai, Amsterdam, Zurich, Johannesburg, Osaka, Singapore, San Jose).
- https://community.oracle.com/customerconnect/discussion/970310/oci-always-free-updated-ampere-a1-compute-allocation — Oracle post 2026-07-21: new A1 allocation 2 OCPU/12 GB, 1,500/9,000; A1 available in home region; Chuncheon NOT available for A1.

## Tactics / PAYG / scripts (index)
- Smaller shape 1 OCPU/6 GB first, resize later; try all ADs; leave fault domain unspecified; capacity report CLI `oci compute compute-capacity-report create` — Oracle docs via https://www.itfriks.com/oracle-cloud-out-of-capacity-a1/ (2026-11-09).
- Retry scripts: hitrov/oci-arm-host-capacity (PHP, archived 2024 per hunt-a1 README); current 2026 forks/successors: https://github.com/moodtuner997/hunt-a1 (cron 2 min, rotates AD-1/2/3, updated for 2/12), https://github.com/alexpua/oci-arm-catcher, https://github.com/wendychen330/oci-arm-retry (GitHub Actions), ITFriks oci-a1-retry (2026-11-09). Polite intervals (60s–5 min); too-fast polling → 429 TooManyRequests.
- PAYG capacity: documented only as "different capacity limits" (FAQ). Community-consensus 2025–26 that PAYG provisions much more easily (deckhand-skill 2026-09-18 "reliable fix, community-consistent"; fullmetalbrackets; klickspell 2026-08-18). Counterpoint: https://jason-finance.com/en/oracle-out-of-host-capacity/ (checked 2026-10-12) PAYG does not add physical capacity, no guarantee, PAYG accounts also hit the error.
- PAYG idle exemption: widely repeated community claim (uk.runmylyfe, den.dance 2026-03-22, aicredits.tech) but the exact quoted "official" line could NOT be found in Oracle docs/FAQ read 2026-11-14 — treat as anecdotal/unverified. PAYG 4/24-free claim: conflicting support reports (InfoQ); one PAYG user uncharged Oct 2026; another analysis (toolfreebie, checked 2026-10-15) says docs give all tenancies 1,500/9,000 and excess would cost ~$27–28/mo. Do NOT plan on 4/24.
- Object storage: Always Free-only accounts 20 GB combined across Standard/IA/Archive + 50k API req/mo; trial/paid accounts 10 GB per tier (via techcommune/rythium summaries of official page, checked Oct–Nov 2026). Block: 200 GB + 5 backups.
